# 电商智能客服系统 · 第 1 章「纯对话」实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 打穿「模型接入 → 流式多轮对话 → Prompt 管理 → 结构化输出 → 上下文控制」最小链路，交付 `/chat`（SSE 流式）与 `/extract`（结构化 JSON）两个接口。

**Architecture:** FastAPI 分层应用（routes / services / prompts / schemas / core）。模型接入走薄工厂 `get_chat_model()` 返回 `BaseChatModel`；对话走 `ChatPromptTemplate`（服务端注入客服 system prompt）+ `astream()` 逐 token；结构化提取走 `with_structured_output`（function calling）；多轮上下文由服务端内存按 `session_id` 持有，按字符数粗估 token 预算裁剪最老消息。

**Tech Stack:** Python 3.12、FastAPI、uvicorn、LangChain（`langchain-core` + `langchain-openai`）、pydantic v2 + pydantic-settings、pytest + pytest-asyncio + httpx。

**Spec:** `docs/superpowers/specs/2026-10-31-ecom-cs-ch01-design.md`

## Review Focus

1. **客户端流式中途断开**：生成器应捕获 `asyncio.CancelledError` 正常收尾，不抛未捕获异常、不残留任务。→ Task 6 加测试。
2. **`session_id` 首次出现（无历史）**：应视为空历史正常对话，不抛 KeyError。→ Task 3 加测试。
3. **token 预算极小 / 裁剪边界**：裁剪后必须保留 system 与最新一轮 user 消息，不得把本轮输入裁掉。→ Task 3 加测试。
4. **上游无任何 token 产出（空回复）**：SSE 至少发一个 `data` 事件（如空 delta），避免客户端永久挂起。→ Task 4 加测试。
5. **模型返回的诉求类型不在枚举内**：`with_structured_output` 用 Pydantic Enum 时非法值会触发解析错误；提取服务应捕获并把非法值兜底为「其他」，而非让接口 500。→ Task 5 加标注样例/测试。
